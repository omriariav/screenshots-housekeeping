# Screenshot Renaming Tool

Rename macOS screenshots with short, meaningful descriptions generated by a vision model. Choose between OpenAI's cloud API and a local [Ollama](https://ollama.com/) model. The selected provider analyzes screenshot content; with Ollama running on `localhost`, images stay on your machine.

## Features

- Select OpenAI or Ollama with one environment variable
- Generates concise, searchable 4–5 word descriptions while retaining original timestamps
- Groups screenshots with the same timestamp so one model request renames the group
- Shows estimated OpenAI cost or zero OpenAI API cost for Ollama processing
- Skips screenshots when the model refuses to describe them
- Gives actionable diagnostics for authentication, unavailable services, and missing models

## Requirements

- macOS (tested on Ventura+)
- Python 3.8+
- One of the following vision-model providers:
  - **OpenAI:** an API key with access to a vision-capable model such as `gpt-4o`
  - **Ollama:** [Ollama](https://ollama.com/) installed and running, plus a locally pulled vision-capable model such as `llama3.2-vision`. Text-only Ollama models cannot describe screenshots.

## Installation

1. Clone the repository, create a virtual environment, and install dependencies.

   ```bash
   git clone <repository-url>
   cd screenshots-housekeeping
   python3 -m venv .venv
   .venv/bin/python -m pip install --upgrade pip
   .venv/bin/python -m pip install -r requirements.txt
   ```

2. Create the configuration file.

   ```bash
   cp env.example .env
   ```

3. Configure one provider as described below.

### OpenAI setup

Set the provider and API key in `.env`:

```bash
LLM_PROVIDER=openai
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o
```

An OpenAI key is required only when `LLM_PROVIDER=openai`. Screenshot content is sent to OpenAI for analysis; review OpenAI's terms, privacy practices, and billing for your account.

### Ollama setup (local)

Install Ollama if needed, start the local service, and pull a vision-capable model:

```bash
ollama serve
ollama pull llama3.2-vision
```

Set the provider and model in `.env`:

```bash
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2-vision
```

The macOS Ollama app normally manages the service for you. No OpenAI account or API key is required in Ollama mode. When `OLLAMA_BASE_URL` is `localhost`, screenshots remain local to your computer. A LAN or remote URL sends images to that Ollama server instead. Do not use plain `http://` for a remote server because screenshot contents will be unencrypted in transit; use HTTPS or a trusted encrypted tunnel/VPN.

## Usage

### Interactive mode

```bash
python3 screenshot_renamer.py
```

The tool checks the chosen provider and configured model, lists screenshots, displays the expected request/cost information, and asks for confirmation before renaming.

### Automatic mode

```bash
python3 screenshot_renamer.py --auto
```

This processes matching screenshots without confirmation, which is useful for automation.

## Configuration

Copy `env.example` to `.env`. `LLM_PROVIDER` is case-insensitive and defaults to `openai` for backward compatibility.

```bash
# Choose exactly one provider: openai or ollama
LLM_PROVIDER=openai

# Required only for OpenAI mode
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o

# Used only for Ollama mode
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2-vision

# Request behavior
MAX_TOKENS=50
API_TIMEOUT=30
MAX_RETRIES=3

# Rename behavior
DESCRIPTION_LENGTH=5
BATCH_SIZE=5

# Optional input folder (defaults to ~/Desktop)
# DESKTOP_PATH=/Users/yourname/Desktop
```

Use a vision-capable model for either provider. If an invalid `LLM_PROVIDER` is configured, the tool stops before scanning or renaming files.

## Output, cost, and privacy

Files are renamed in place using this pattern:

```
[Original Filename] - [AI Description].png
```

For example:

```
Screenshot 2025-01-15 at 14.30.22 - Code editor Python file.png
```

A session log is written to `~/Desktop/screenshot_rename_log.txt` (or the configured `DESKTOP_PATH`). OpenAI mode shows estimated/actual cloud API cost based on the tool's pricing approximation. Ollama mode incurs no OpenAI API charge; model downloads, disk use, power use, and any remote Ollama-server costs remain your responsibility.

## Automation setup

You can invoke automatic mode from a macOS Folder Action or LaunchAgent after new screenshots appear. The automation environment must be able to read the same `.env` configuration. In Ollama mode it must also be able to reach the running Ollama service.

First make the checked-in runner executable:

```bash
chmod +x scripts/automator-folder-action.sh
```

In Automator, create a **Folder Action**, attach it to **Desktop**, add **Run Shell Script**, select `/bin/zsh`, and invoke the runner using the absolute path to your checkout:

```zsh
/absolute/path/to/screenshots-housekeeping/scripts/automator-folder-action.sh
```

The runner discovers the repository path automatically, uses `.venv/bin/python`, waits briefly for macOS to finish writing the screenshot, prevents overlapping runs, and appends diagnostics to `automator.log`. Before enabling automation, run it manually once to verify the selected provider. See [Apple's Automator workflow guide](https://support.apple.com/guide/automator/create-a-workflow-aut7cac58839/mac) for the current Folder Action interface.

## Troubleshooting

### OpenAI: API key not found or authentication fails

Verify that `.env` contains `LLM_PROVIDER=openai` and a valid `OPENAI_API_KEY`. Check that the key has access to the configured vision model and that your account's billing/usage limits permit requests.

### Ollama: service is unavailable

Start the service:

```bash
ollama serve
```

If you use the macOS Ollama app, open it and retry. Confirm that `OLLAMA_BASE_URL` matches the service address.

### Ollama: configured model is unavailable

List local models, then pull the configured vision model or update `OLLAMA_MODEL`:

```bash
ollama list
ollama pull llama3.2-vision
```

### The model cannot analyze images

Text-only models cannot generate screenshot descriptions. Configure a model with vision/image support and retry.

### No screenshots are found

The default scan location is `~/Desktop`, and filenames must follow a supported macOS Screenshot/Screen Shot pattern. Set `DESKTOP_PATH` to scan a different writable directory.

### Permission denied or renames fail

Check that the configured folder is writable and that the screenshot is not open or locked by another app. Review `screenshot_rename_log.txt` for the full error.

## Tests
